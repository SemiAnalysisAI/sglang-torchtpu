1. End-to-End Hybrid Prefill + Megakernel Decode Architecture

SGLang executes chunked and multimodal prefill (ForwardMode.EXTEND) using its native Qwen3VLDecoderTpuCompilePolicy and gmm_v2 MoE kernel over paged caches, then performs a one-time on-device state handoff into the 93-layer Pallas decode megakernel (ForwardMode.DECODE).

2. Zero-Copy 5D Expert Weight Sharing & Per-Core 97 GB HBM3e Footprint

To avoid duplicating 39.64 GiB/rank of MXFP4 routed expert weights (which would exceed 95 GiB HBM) and to prevent torch_tpu from re-materializing tensor views (_base is not None) across compiled graphs, stack_sglang_moe_experts_in_place() stacks all 92 MoE layers into two 5D uint8 storage-owning base tensors shared directly between prefill and decode.

In mk_e2e5, TpuCopyInsertion::AddSpecialCaseCopies inserted 2 × 3.85 GiB = 7.70 GiB (5.22 ms/step) of HBM state copies because OutputHasToBeConstant returns true for communicating custom-calls (has_communication=true, collective_id=21). With return_state_updates=True in mk_e2e6, stack() returns compact [B, ...] KDA state rows and 128-token MLA cache tiles updated in-place outside the custom-call via jax.lax.dynamic_update_slice, reducing copy overhead from 5,219.8 µs to 46.5 µs (99.1% reduction)!
